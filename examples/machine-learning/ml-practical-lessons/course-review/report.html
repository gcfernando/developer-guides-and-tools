Machine learning course beginner review

This report describes the course before the revision. Read the response to each finding and the new check results. Start the revised course at Start here.

Review date: 27 November 2026. Audience: the course author. Folder: ml-practical-lessons.

This is a useful practical Python workbook, but it does not yet provide a complete path from zero prior knowledge to independent ML competence. A beginner can reproduce several well-supported examples. Explaining the choices, diagnosing unfamiliar failures and solving a new problem independently require a stronger teaching sequence and assessment.

I interpret ?if a baby read this? as a learner with no ML knowledge and little or no programming experience. Literal infant suitability is not a meaningful measure. Reading alone cannot demonstrate mastery; the course should promise observable skills, supported practice and independent transfer.

These are expert judgments about the supplied learning design, not measured learner-completion rates. A novice pilot is needed to establish actual ease of use.

What should be preserved

  • The delivery-time story gives learners a familiar thread through input, prediction, evaluation and service use.
  • Small data tables, known outputs, edit-and-rerun tasks, diagrams and explanatory alt text make first experiments inspectable.
  • The outlier lesson correctly asks for source verification before changing an unusual value.
  • The saved-scaler example correctly demonstrates values outside the training range without silently refitting.
  • The later split, threshold, calibration and grouped-error labs teach valuable judgment. They do not force every technique to improve the result.
  • The capstone has chronological splits, a baseline comparison, saved preprocessing, input rejection, metadata, later-batch monitoring and a useful ten-point self-check.
  • The workbook discloses synthetic data, small-sample limits and platform verification limits. Those qualifications should remain.
  • The HTML includes responsive layout, search, keyboard focus styling, themes and copy controls. The review does not claim those features are absent.

Complete actionable findings register

71 findings: 33 P1, 37 P2 and 1 P3. These include cross-cutting teaching gaps and their lesson-specific manifestations; they are not 71 independent runtime bugs. P1 means address before presenting the course as an independent zero-prerequisite learning path. P2 improves understanding, transfer or delivery. P3 is a scope-dependent extension. Evidence types distinguish reproduced defects from design judgments and validation gaps.

Location: README.md; workbook lines 21-80

Why a beginner gets stuck: Completing scripts can be confused with understanding ML or professional readiness.

A repeatable beginner lesson template

  1. One question: for example, how many minutes might a 4 km delivery take?
  2. Before starting: name the previous skill and required files. State the lesson's estimated effort after piloting.
  3. See a tiny example: explain each row, column and unit before code.
  4. Predict first: ask for an answer or a choice and a reason.
  5. Work it by hand: show the arithmetic or decision on one row.
  6. Run the smallest useful code: connect each important line to the same row. Put deeper implementation details behind an optional explanation.
  7. Read the result: explain meaning and limitations, rather than only matching a number.
  8. Change one thing: specify the file, cell, expected effect, expected invariants and whether an old measured answer must be cleared.
  9. Recover from one mistake: include a deliberately invalid input with a friendly next action.
  10. Transfer: give one similar unsolved case, then an explained answer.
  11. Check understanding: three short questions and a concrete completion condition.
  12. Continue: link the next required lesson and any optional depth.

Example of the first concept before Python

Past deliveries took 12 minutes at 1 km, 14 at 2 km and 16 at 3 km. In this invented example the time rises by two minutes for each extra kilometre. A matching rule is 10 + 2 x distance. For 4 km, calculate 10 + 2 x 4 = 18 minutes. These deliberately exact rows help explain the mechanism.

Now ask the learner to estimate 5 km before running anything. Then add a real-looking observation: a second 3 km delivery took 19 minutes. Ask why the same distance might have a different time. Explain that traffic and other unrecorded conditions create uncertainty. Only after that should fitting a line and evaluating unseen deliveries be introduced.

Mastery gates that demonstrate competence

Use observable gates rather than the number of ZIPs opened. A suggested progression is: explain a prediction; prepare a new record safely; choose an evaluation design; build and defend an unseen project; and respond to a later failure. A learner should be able to explain both a good result and a reason not to trust it. Professional competence also needs the ability to decide that ML is unnecessary.

For an independent capstone, assess five areas: problem and baseline; data quality and availability; split and leakage control; evaluation and uncertainty; and communication and reproducibility. Require evidence in every area. Instructors should supply hints and worked answer rationales, with the complete solution revealed only after the independent attempt.

Technical references for specific recommendations

The recommendation to distinguish dependency groups from identical feature values is based on the split question and provenance of observations. Grouped evaluation is intended for genuinely related observations, such as repeated measurements of the same subject; equal rounded feature values alone do not establish that relationship. Scikit-learn cross-validation guide.

The chi-square feature-selection API is described for nonnegative integer count/frequency-style features. A continuous feature may need appropriate binning rather than being used merely because its values are positive. This supports revising the elapsed-minutes teaching example. Scikit-learn chi2 reference.

Training-only learned preprocessing and pipelines should be explicit early concepts; the course already implements these correctly in several important exercises. Scikit-learn common pitfalls guide.
