📚What you will build

📅 Checked 7 November 2026Same section in: Claude Code · OpenAI Codex

You will build a small, read-only code review team in GitHub Copilot: Copilot CLI (copilot) and Copilot Chat in VS Code. One leader and two specialists, first in a practice repository, then in your own projects or globally. Every step says where to do it, what to type, what you should see, and what to check if not.

👑 review-lead

Custom agent with the agent tool: calls both specialists as subagents and merges their reports. Skill review-plan.

↓ starts both at the same time, waits, merges one report ↓
🧭 path-mapper

Maps the changed code paths. No edit tool. Skill map-code-paths.

🐛 bug-hunter

Finds bugs and missing tests; may run npm test. No edit tool. Skill find-bugs-and-test-gaps.

📖Glossary: words used in this guide

📅 Checked 7 November 2026Same section in: Claude Code · OpenAI Codex

Every technical word used in this guide, in plain English.

Agent
An AI assistant working on a task with tools (reading files, running commands).
Sub-agent
An agent started by another agent for one job. It has its own memory of the task and reports back once.
Leader (main agent)
The agent you talk to. In this guide it splits the review, starts the specialists and merges their reports.
Skill
A folder with a SKILL.md file: a short description plus step-by-step instructions, loaded only when needed.
Instructions
Plain-text rules the tool reads automatically, such as AGENTS.md.
Prompt
The message you type.
Model
The AI 'brain' that answers. Bigger models think better; smaller ones are faster and cheaper.
Context
Everything the model can see at once: instructions, files it read, and the conversation.
Token
A small piece of text. Usage limits and prices are counted in tokens.
Terminal
The window where you type commands. In VS Code: Terminal → New Terminal.
PowerShell / bash / zsh
Terminal languages: PowerShell on Windows, zsh on macOS, bash on Linux.
CLI
Command-line interface: a program you run by typing its name in the terminal.
VS Code extension
An add-on that puts the tool's chat panel inside VS Code.
Repository (repo)
A project folder tracked by Git.
Branch
A separate line of work in a repository. Here: feature/discount-codes holds the change to review.
Commit
A saved snapshot of the files in Git.
Diff
The list of lines that changed between two versions. git diff main...HEAD shows what this branch changed.
YAML header (front matter)
The block between two --- lines at the top of an agent or skill file: name, description and settings.
TOML / JSON
Two formats for settings files. TOML uses key = value; JSON uses { "key": value }.
Home folder (~)
Your personal folder: C:\Users\you, /Users/you or /home/you. Global files live here.
Project vs global
Project files sit inside one repository and are shared through Git; global files sit in your home folder and work everywhere.
Sandbox / permissions
Limits on what the AI may read, run or change, enforced by the tool.
MCP server
A connector that gives the AI extra tools, such as access to GitHub issues or a database.
Hook
A command the tool runs automatically at certain moments, for example after every file edit.
Fleet
Copilot CLI mode (/fleet) that splits one task into parallel sub-agents by itself.
Auto
Copilot picks the model for each request.

📁Project or global: where files go

📅 Checked 7 November 2026Same section in: Claude Code · OpenAI Codex

Every feature can live in two places. Pick Project to share with your team through Git, or Global to use it in every project on your computer.

FeatureProject Project pathGlobal Global path
InstructionsAGENTS.md, .github/copilot-instructions.md, .github/instructions/*.instructions.md~/.copilot/copilot-instructions.md
Custom agents.github/agents/<name>.agent.md~/.copilot/agents/<name>.agent.md
Skills.github/skills/, .agents/skills/ or .claude/skills/ ✓ Tested~/.copilot/skills/ or ~/.agents/skills/
CLI settings.github/copilot/settings.json (+ settings.local.json for just you)~/.copilot/settings.json
Trusted folders, saved approvals (Copilot writes them)–~/.copilot/config.json, ~/.copilot/permissions-config.json
VS Code settings.vscode/settings.jsonUser settings

Which one wins

  • Agents with the same name: Copilot CLI uses the personal one 📖 From docs.
  • Instructions: all applicable files are combined; GitHub documents no priority order and removes exact duplicates 📖 From docs.
  • Settings: command-line flags apply to one session; settings.local.json holds your personal repository overrides. copilot config --list shows settings ✓ Tested.
  • COPILOT_HOME moves ~/.copilot.

How to create files

Create every file in the VS Code Explorer (New File…, type the path, paste, save). Copilot commands are the same in PowerShell, bash and zsh; in PowerShell keep the single quotes in values such as 'shell(git push)'. For global files, open the folder first with the command in Part E.

🧩If the file already exists

Agent and skill files: one file per role, nothing to merge; if a file of the same name exists, rename one. settings.json: JSON, one outer object; prefer copilot config <key> <value>, which edits it for you. Instruction files: add your lines anywhere.

Write a description that gets picked

  • Say what it does, then when to use it: “Maps which functions a change touches. Use when asked what changed…”
  • Use the words people really type: review my branch, find bugs, what changed.
  • Make each description different from the others.
  • Keep it short (the standard allows 1,024 characters; only the description is visible until the skill is used).
  • name = folder name: lowercase letters, digits and hyphens, at most 64 characters. Otherwise the skill does not load.

🛡️Stay safe and control cost

📅 Checked 7 November 2026Same section in: Claude Code · OpenAI Codex

AI agents can read your files and run commands. Five habits keep that safe.

HabitWhyHow in this guide
Keep reviews read-onlyA reviewer has no reason to change filesNo edit tools in the agent files, plus the permission settings in question 4
Never put secrets in instruction, agent or skill filesThey are plain text, often committed to Git and sent to the modelKeep keys in environment variables or your tool's sign-in; add .env to .gitignore
Read third-party skills and agents before installingA skill is instructions the AI will follow, and may run commandsOpen the SKILL.md and look for shell commands, URLs and 'pre-approved' tools
Treat repository text as untrustedA comment in code can try to give the AI orders (prompt injection)Keep approvals on; read what a command does before you approve it
Avoid 'allow everything' modesThey remove every safety checkDo not use --allow-all, --yolo or /allow-all for reviews

🎓Check yourself: 8-question quiz

📅 Checked 7 November 2026Same section in: Claude Code · OpenAI Codex

Eight questions, one per topic. Answer in your head, then open the answer.

1. Where does a project custom agent go?
  1. .github/agents/<name>.agent.md
  2. .copilot/agents.json
  3. AGENTS.md
Answer: A. The name must end in .agent.md; personal ones go in ~/.copilot/agents/.
2. What lets review-lead call other agents?
  1. "agent" in its tools list
  2. A model line
  3. A skill
Answer: A. Without the agent tool it works alone.
3. A personal and a project agent have the same name. Which does Copilot CLI use?
  1. The project one
  2. The personal one
  3. Both
Answer: B. Personal wins in Copilot CLI.
4. How are several instruction files combined?
  1. Only the newest is used
  2. All are used; no documented priority
  3. Global always wins
Answer: B. Avoid contradicting rules.
5. How do you make the whole chat use review-lead?
  1. copilot --agent review-lead (or /agent, or the VS Code drop-down)
  2. Mention it once
  3. Rename it
Answer: A. The selected agent answers every prompt.
6. What do you write after model:?
  1. The display name, e.g. Claude Haiku 5.5
  2. The model ID from /model, e.g. claude-haiku-5.5
  3. A list of names
Answer: B. Copilot CLI expects one model ID.
7. Which flags keep a review read-only in the CLI?
  1. --allow-all
  2. --deny-tool='shell(git commit), shell(git push), write'
  3. --yolo
Answer: B. Deny always beats allow.
8. Which is a CLI-only feature?
  1. The agent drop-down
  2. /fleet and /usage
  3. Reading AGENTS.md
Answer: B. Chat in VS Code has its own controls.
