Your four-agent team

You talk to one lead. The lead assigns work to a developer, a QA tester and a DevOps agent, then combines their results. Follow the steps below to create the files and start the team.

RoleJob
LeadUnderstands the request, chooses specialists and manages the work.
DeveloperChanges application code.
QA testerWrites and runs checks; reports defects to the lead.
DevOpsPrepares build/CI files and delivery instructions.

You will get complete Markdown instructions, product-specific configuration, four skills, model choices and normal prompts. C# is used for the optional runnable example. The team setup also works with an existing project once you change its project settings.

Local validation: files, scripts and C# examples are checked separately. Authenticated agent execution, automatic routing, parallel activity and live recovery remain documented routes to verify in your own client.

1. Install and sign in

Where: open VS Code and choose Terminal → New Terminal. The terminal is where you type commands. AI chat is where you type requests.

  1. Install Git, .NET 10 SDK for the C# example, and GitHub Copilot.
  2. Use the matching installer below. It downloads the official client; read the linked setup documentation first.
  3. Restart the terminal, check the versions, then sign in.
Windows installer

Copilot CLI needs PowerShell 6 or later; PowerShell 7 is a straightforward choice. Native Windows and WSL are separate tool installations. Choose one environment and keep using it.

macOS/Linux installer

Expect version numbers. Git must be 2.28 or newer; use .NET SDK 10.x for this example. Run copilot, follow sign-in prompts and send Reply READY without using tools. in its chat. Expect a short reply, then exit the client.

Check: The client can answer a basic request.

If different: If a command is missing, restart the terminal or repair the installation. For sign-in or organization restrictions, resolve account access first. AI use needs a connection and may cost money; local files and C# checks do not need an AI account.

What happens when an agent fails or gets stuck?

Failure recovery is already configured in .agent-team/recovery.md. Every role reads it. To change the limits, edit that file and start a fresh session; do not invent YAML settings such as retry_count and expect the client to enforce them.

What happenedSpecialist actionLead action
Temporary tool timeoutConfirm the old attempt ended; safely retry once.Keep other completed work.
Permission denied, missing SDK or unsupported toolSkip the identical retry; report blocked.Choose an allowed smaller method or explain the setup blocker.
Checks finish and an assertion failsReturn the actual defect evidence.Send the defect to developer, then ask QA to recheck the finished fix.
Specialist crashes with no reportThere may be no specialist reply.Record actual task status/error; never invent its message.
Fallback also fails, or old task status is unknownStop further attempts.Preserve good results and report partial.

9. See how parallel work and handoffs happen

Parallel means agents work at the same time. Use it for independent tasks. Work that needs another task’s result must wait.

  1. Lead plans: define behavior and agree the public method signature.
  2. Independent planning: developer inspects source, QA plans cases and DevOps inspects the build. These can run together without edits.
  3. Separate edits: developer owns source, QA owns checks and DevOps owns the workflow. They may edit in parallel after agreeing the interface, provided their files do not overlap.
  4. QA verifies: after edits finish, QA runs one check process against stable code. DevOps inspects the workflow without starting a competing build.
  5. Lead finishes: collect results, resolve defects or blockers and report evidence.

Each specialist has its own task context. The lead sends the requirements and relevant facts; it must not assume the specialist can see the whole user conversation. Specialists return to the lead, which chooses the next action.

Do not ask the user to copy reports between agents. The client delivers task results to the lead. The lead may continue or message a specialist where the client supports it. If continuation is unavailable, the lead starts a fresh task with the full history and remaining budget.

Check: Parallel tasks have distinct file ownership, and verification waits for stable inputs.

If different: If two tasks need the same file, the lead pauses one and assigns an order. If a client cannot run tasks concurrently, run them sequentially and say so.

Personal settings and safe cleanup

Start with project files so the setup affects only this project. Personal files can shadow project agents; organization policy may add restrictions. Before changing a personal file, keep its original contents.

To remove this team, close its sessions and remove only the role, skill and configuration additions you made. Restore backed-up settings that existed before. In a disposable practice folder, verify its exact location in the file manager before deleting it. Preserve your real project and unrelated customizations.

Check your understanding

1. Which agent starts?
The main lead session. Codex uses AGENTS.md; Claude/Copilot are launched with --agent lead.
2. Do all specialists run for every prompt?
No. The lead chooses the relevant roles from the work required.
3. What is the difference between an agent and a skill?
An agent is a worker with a role; a skill is a reusable checklist it follows.
4. Can everyone edit the same file in parallel?
No. Assign one writer per file, or do dependent work in sequence.
5. What happens after a temporary failure?
Confirm the old action ended and safely retry once; then report to the lead if still blocked.
6. Who chooses the alternate path?
The lead explicitly assigns one allowed fallback and carries the existing counts.
7. Does a QA assertion failure mean the runner broke?
No. A completed failing check is evidence of behavior to investigate.
8. Can a new agent reset the budget?
No. Attempts and completed evidence carry forward.
9. Where are retry rules configured?
In .agent-team/recovery.md, as instructions read by every role.
10. Do Markdown instructions enforce permissions?
No. The client’s real tools, approvals and sandbox control access.
11. Does a prepared workflow prove CI passed?
No. Remote CI needs a separately authorized run and its actual result.
