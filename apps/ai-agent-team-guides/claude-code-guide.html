📚What you will build

📅 Checked 7 November 2026Same section in: OpenAI Codex · GitHub Copilot

You will build a small, read-only code review team in Claude Code: one leader and two specialists. You build it in a practice repository first, then use it in your own projects or globally. The guide follows your questions in order, and every step says where to do it, what to type, what you should see, and what to check if not.

👑 review-lead

Runs as the main session. Reads the diff, starts both specialists at once, waits, writes one report. Opus · skill review-plan.

↓ starts both at the same time, waits, merges one report ↓
🧭 path-mapper

Maps the changed code paths. Read-only. Haiku · skill map-code-paths.

🐛 bug-hunter

Finds bugs and missing tests; may run the tests. Read-only. Sonnet · skill find-bugs-and-test-gaps.

📖Glossary: words used in this guide

📅 Checked 7 November 2026Same section in: OpenAI Codex · GitHub Copilot

Every technical word used in this guide, in plain English.

Agent
An AI assistant working on a task with tools (reading files, running commands).
Sub-agent
An agent started by another agent for one job. It has its own memory of the task and reports back once.
Leader (main agent)
The agent you talk to. In this guide it splits the review, starts the specialists and merges their reports.
Skill
A folder with a SKILL.md file: a short description plus step-by-step instructions, loaded only when needed.
Instructions
Plain-text rules the tool reads automatically, such as AGENTS.md.
Prompt
The message you type.
Model
The AI 'brain' that answers. Bigger models think better; smaller ones are faster and cheaper.
Context
Everything the model can see at once: instructions, files it read, and the conversation.
Token
A small piece of text. Usage limits and prices are counted in tokens.
Terminal
The window where you type commands. In VS Code: Terminal → New Terminal.
PowerShell / bash / zsh
Terminal languages: PowerShell on Windows, zsh on macOS, bash on Linux.
CLI
Command-line interface: a program you run by typing its name in the terminal.
VS Code extension
An add-on that puts the tool's chat panel inside VS Code.
Repository (repo)
A project folder tracked by Git.
Branch
A separate line of work in a repository. Here: feature/discount-codes holds the change to review.
Commit
A saved snapshot of the files in Git.
Diff
The list of lines that changed between two versions. git diff main...HEAD shows what this branch changed.
YAML header (front matter)
The block between two --- lines at the top of an agent or skill file: name, description and settings.
TOML / JSON
Two formats for settings files. TOML uses key = value; JSON uses { "key": value }.
Home folder (~)
Your personal folder: C:\Users\you, /Users/you or /home/you. Global files live here.
Project vs global
Project files sit inside one repository and are shared through Git; global files sit in your home folder and work everywhere.
Sandbox / permissions
Limits on what the AI may read, run or change, enforced by the tool.
MCP server
A connector that gives the AI extra tools, such as access to GitHub issues or a database.
Hook
A command the tool runs automatically at certain moments, for example after every file edit.
CLAUDE.md
Claude Code's instructions file; it imports AGENTS.md.
Slash command
A command typed in the chat that starts with /, such as /agents or /model.

📄Every file explained

Each file has one job. Read the cards once; later you only need the ones for the feature you are setting up.

📄AGENTS.md
Project
What
Plain-English rules about the project that every AI tool can read: what the code is, the test command, what agents must never do.
When
Always, in every repository you use with AI tools.
Why
One file that Claude Code, Codex and Copilot all understand, so you write the rules once.
👉 In this guide: the review rules and git diff main...HEAD -- src test
📄CLAUDE.md
Project
What
Claude Code's own instructions file, read at the start of every session. Its line @AGENTS.md pulls in AGENTS.md.
When
Always in a project you use with Claude Code.
Why
Claude Code reads CLAUDE.md, not AGENTS.md, so this file connects the two.
👉 In this guide: two lines that import AGENTS.md
📄CLAUDE.local.md
Project
What
Your private instructions for one project. Not committed to Git.
When
You want a personal habit in one project without changing the team's file.
Why
Keeps personal preferences out of the shared rules.
📄~/.claude/CLAUDE.md
Global
What
Your personal instructions for every project on this computer.
When
Rules you always want, such as 'explain in plain English'.
Why
Write them once instead of in every repository.
👉 In this guide: “My rules for every project”
📄.claude/agents/<name>.md
Project Global
What
One agent (role): a header with name, description, tools, model and skills, then the role's instructions.
When
You want a reusable specialist or a leader.
Why
A fixed job, fixed tools and a fixed model every time.
👉 In this guide: review-lead, path-mapper, bug-hunter
📄.claude/skills/<name>/SKILL.md
Project Global
What
A skill: a description plus step-by-step instructions, loaded only when needed.
When
A job has a fixed procedure or report format.
Why
Keeps long instructions out of the way until they are used.
👉 In this guide: review-plan, map-code-paths, find-bugs-and-test-gaps
📄.claude/settings.json
Project
What
Shared settings for the repository, mainly permissions (allow / deny rules).
When
You want everyone's sessions to have the same safety rules.
Why
Rules are enforced by the tool, not just requested in text.
👉 In this guide: allow git diff and npm test; deny git push, Edit and Write
📄.claude/settings.local.json
Project
What
Your personal settings for this repository. Not committed.
When
You need a permission only you should have.
Why
Overrides the shared file without changing it for others.
📄~/.claude/settings.json
Global
What
Your personal settings for every project (permissions, default model, environment variables).
When
Defaults you always want.
Why
Applies everywhere unless a project overrides it.
👉 In this guide: allow read-only git commands; deny git push
📄~/.claude.json
Written by the tool
What
Account, trusted folders and app state, written by Claude Code.
When
Never edit by hand.
Why
Claude Code keeps it up to date itself.
✨Tip

Rule of thumb: instructions (.md) say what to do, settings (.json) enforce what is allowed, agents are roles, skills are procedures.

📁Project or global: where files go

📅 Checked 7 November 2026Same section in: OpenAI Codex · GitHub Copilot

Every feature can live in two places. Pick Project to share with your team through Git, or Global to use it in every project on your computer.

FeatureProject Project path (inside the repository)Global Global path (home folder)
Shared instructionsCLAUDE.md (can import AGENTS.md)~/.claude/CLAUDE.md
Instructions just for you in one projectCLAUDE.local.md–
Agents.claude/agents/<name>.md~/.claude/agents/<name>.md
Skills.claude/skills/<name>/SKILL.md~/.claude/skills/<name>/SKILL.md
Settings and permissions.claude/settings.json (shared), .claude/settings.local.json (just you)~/.claude/settings.json
Account and trust (Claude writes it)–~/.claude.json (do not edit)

Which one wins

  • Settings, highest first: organization (managed) → command line → .claude/settings.local.json → .claude/settings.json → ~/.claude/settings.json. Permission lists are combined 📖 From docs
  • Instructions: global and project CLAUDE.md are both loaded. Write project exceptions in the project file.
  • Agents with the same name: project wins. Skills with the same name: personal wins 📖 From docs

Which terminal and how to create files

Create every file in the VS Code Explorer (New File…, type the path, paste, save): this works the same on Windows, macOS and Linux. Commands that differ by system are shown as a PowerShell block and a bash/zsh block. Global files: open the folder first with the command in Part E.

🧩If the file already exists

settings.json is strict JSON: one outer { }, no comments, no trailing commas. Keep one "permissions" object and add new entries to its existing "allow" / "deny" lists. CLAUDE.md: add your lines anywhere. Check after editing with claude doctor: a broken file shows Invalid settings … Invalid or malformed JSON ✓ Tested.

Write a description that gets picked

  • Say what it does, then when to use it: “Maps which functions a change touches. Use when asked what changed…”
  • Use the words people really type: review my branch, find bugs, what changed.
  • Make each description different from the others.
  • Keep it short (the standard allows 1,024 characters; only the description is visible until the skill is used).
  • name = folder name: lowercase letters, digits and hyphens, at most 64 characters. Otherwise the skill does not load.

🛡️Stay safe and control cost

📅 Checked 7 November 2026Same section in: OpenAI Codex · GitHub Copilot

AI agents can read your files and run commands. Five habits keep that safe.

HabitWhyHow in this guide
Keep reviews read-onlyA reviewer has no reason to change filesNo edit tools in the agent files, plus the permission settings in question 4
Never put secrets in instruction, agent or skill filesThey are plain text, often committed to Git and sent to the modelKeep keys in environment variables or your tool's sign-in; add .env to .gitignore
Read third-party skills and agents before installingA skill is instructions the AI will follow, and may run commandsOpen the SKILL.md and look for shell commands, URLs and 'pre-approved' tools
Treat repository text as untrustedA comment in code can try to give the AI orders (prompt injection)Keep approvals on; read what a command does before you approve it
Avoid 'allow everything' modesThey remove every safety checkDo not use --dangerously-skip-permissions or the bypassPermissions mode for reviews

🎓Check yourself: 8-question quiz

📅 Checked 7 November 2026Same section in: OpenAI Codex · GitHub Copilot

Eight questions, one per topic. Answer in your head, then open the answer.

1. Where does a project agent file go?
  1. .claude/agents/<name>.md
  2. agents.json in the root
  3. .github/agents/<name>.md
Answer: A. Project agents live in .claude/agents/; personal ones in ~/.claude/agents/.
2. What makes something a sub-agent?
  1. It has a smaller model
  2. Another session starts it for one task and gets one report back
  3. It lives in your home folder
Answer: B. Any agent becomes a sub-agent when another session hands it a task; it never sees your chat.
3. When is a skill's full text loaded?
  1. Always, at start
  2. When the request matches its description, you type /name, or an agent lists it in skills:
  3. Never automatically
Answer: B. At start Claude only sees names and descriptions.
4. You have ~/.claude/CLAUDE.md and a project CLAUDE.md. Which is used?
  1. Only the project one
  2. Only the global one
  3. Both, added together
Answer: C. Instruction files are combined; avoid contradictions.
5. How do you make review-lead the agent you talk to?
  1. Type @review-lead
  2. Start with claude --agent review-lead
  3. Rename it to main.md
Answer: B. @ calls it as a sub-agent; --agent makes it the main session.
6. Which model fits path-mapper best?
  1. haiku
  2. fable
  3. opus
Answer: A. Mapping is simple searching: fast and cheap is enough.
7. You type a prompt without naming an agent, in a plain claude session. Who answers?
  1. Always bug-hunter
  2. Claude itself, unless it decides a description matches
  3. Nobody
Answer: B. Automatic delegation is the model's choice.
8. Which works only in the terminal, not in the VS Code panel?
  1. Typing @ to pick an agent
  2. claude --agent review-lead
  3. /model
Answer: B. Start the leader in VS Code's integrated terminal.
